# Модели предметной области

Рисунки в этой папке соответствуют рисункам 4–6 отчета.

## Основной процесс
Обращение -> проверка и оценка -> согласование -> оформление и выдача ->
хранение и контроль -> выкуп или проверка оснований и реализация.
Отказ завершает процесс. Неистекший льготный срок возвращает управление к
хранению и контролю. Реализация не автоматизирована.

## Связи данных
- Клиент (1) — Договор (0..*).
- Сотрудник (1) — Договор (0..*).
- Договор (1) — Залоговая вещь (1..*).
- Договор (1) — Операция (0..*).
- Сотрудник (1) — Операция (0..*).

Ключи, атрибуты и ограничения приведены в отчете.
JSON — только проекция сущности Договор; это не физическая база данных.

## Алгоритмы
А1: валидация -> число дней -> простые проценты -> ограничение -> округление -> сумма.
А2: перебор -> валидация и уникальность -> проверка статуса и даты -> добавление в список.
Память А2 O(n+k): множество просмотренных номеров и результирующий список.

## Границы учебной реализации
Дата конца льготного срока указывается явно. Программа не рассчитывает ПСК,
не выдает разрешение на реализацию и не обрабатывает частичные платежи.
Все записи вымышленные. Личный GitHub-репозиторий создает студент по памятке.
